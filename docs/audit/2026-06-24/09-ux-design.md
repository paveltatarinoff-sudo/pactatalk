## 4. Non-obvious decisions

- **Single-page, single-CTA architecture.** Everything funnels to `t.me/PactaTalkBot`; no email capture, no waitlist, no pricing, no auth (`page.tsx:3`, three CTA call sites). Rationale visible: bot lives in Telegram, so launching there is the only sensible conversion. Trade-off: zero retention surface if the user is not ready to start a couple's conversation right now.
- **H1 leads with the user's pain, not the product name.** "Когда в паре пора обсудить важное, но самим удержать разговор уже не получается" (`page.tsx:256-258`). Product name introduced in sub-copy. Looks deliberate (problem-first positioning), confirmed by parallel structure in the OG image headline "Трудные разговоры в паре — спокойнее и яснее" (`opengraph-image.tsx:126`).
- **Telegram chat mock-up as hero visual** (`page.tsx:277-347`) instead of a couple photo. Decision: show the product surface (Telegram bubbles) above the fold, push the emotional photos to a later section. Removes ambiguity that this is in fact a Telegram bot.
- **Brand wordmark is duplicated in the header** (`page.tsx:226-239`): logo image already says "PACTA" and is followed by `<div>PACTA — AI</div>` + tagline. Rationale unclear — may be a designer choice to anchor the lockup, or leftover from an earlier logo iteration.
- **No analytics/consent script in SSR HTML.** Cross-check: specialist #5 owns PostHog. From this dimension only: cached HTML has zero third-party `<script src>` other than Next.js bundles (`docs/audit/_data/landing/index.html` head section).
- **Dynamic OG route exists but is not the served URL.** `app/opengraph-image.tsx` builds a 1200×630 image at request time; production page serves static `/landing/og-card.png`. Suggests a manual hand-uploaded asset overrode the route — file is not under source control (rationale unclear).
- **Two non-trivial photo files in `public/landing/` are not optimized** (2.4 MB PNG + 246 KB JPG). Next/Image will handle delivery, but origin payload + git LFS-less PNG bloat the repo. Rationale unclear.

## 5. Risks & landmines

- **OG / Twitter preview will break on next redeploy.** Production HTML hard-codes `https://pactatalk.app/landing/og-card.png`; the file is not in `gcs-landing-v2/public/`. Source-of-truth `layout.tsx:28` points to the dynamic `/opengraph-image` route which currently 404s in production. Trigger: any redeploy from current HEAD that overwrites the manually uploaded static PNG → Telegram and Twitter shares lose the card. Diagnosis: `curl -I https://pactatalk.app/opengraph-image` → 404; `curl -I https://pactatalk.app/landing/og-card.png` → 200.
- **No privacy / terms / contact destination.** FAQ promises "данные можно удалить" (`page.tsx:79-81`) but the page exposes no link, no email, no policy. If a visitor asks a privacy-conscious question (and the bot is about intimate couple conversations, where this matters most), the only escalation is the bot itself. Trigger: any cautious visitor will bounce without a policy page.
- **No conversion proof.** Zero testimonials, zero usage stats, zero expert / clinician endorsement, zero sample-transcript artefact. Combined with "AI-фасилитатор для пары" being a novel category, a sceptical visitor has nothing external to lean on. Trigger: the page asks the user to import their partner into a vulnerable conversation with no third-party trust signal.
- **Mobile header loses persistent CTA below the hero.** `md:inline-flex` (`page.tsx:245`) hides the header Telegram button on phones. After the hero scrolls off, the next CTA opportunity is the final banner (~6+ sections down). No sticky CTA. Trigger: a mobile visitor reading the FAQ has to scroll back up or forward to act.
- **2.4 MB unoptimized hero PNG.** `public/landing/left-conflict-selected.png`. Next/Image will resize on serve, but the source artefact is large and bloats the repository and CI artifact size. Trigger: anyone cloning / building from cold cache.
- **Brand pill on red CTA banner.** `BrandWord` (`globals.css:60-65`) renders a warm-coral + telegram-blue gradient pill, but the final CTA banner background is `linear-gradient(135deg,#d94841,#b83731)` (`page.tsx:484`). The pill effectively disappears or muddies against the red. Trigger: visual regression already shipped.
- **Header double-wordmark.** Logo art + adjacent textual wordmark + tagline (`page.tsx:225-239`) reads as a logo design accident. Cosmetic, not load-bearing.
- **No structured data, no `robots.txt`, no `sitemap.xml`.** SEO discoverability is whatever Google's crawler infers from a single page. For a niche product this may be acceptable, but FAQPage / Organization JSON-LD would be cheap wins. Trigger: organic search visibility.

## 6. Open questions for the owner

- Is `/landing/og-card.png` (the file currently serving social previews) intended to be the source of truth, or should `app/opengraph-image.tsx` win? If the dynamic route is the answer, the static file needs to be removed and the deploy verified. If the static file is the answer, `layout.tsx:28` should be updated.
- Is the absence of a Privacy / Terms / Contact link a deliberate "stealth-launch, talk to me in Telegram" stance, or an oversight before public traffic? If the latter, the FAQ wording about data deletion is a soft promise without a destination.
- Why is the brand wordmark rendered twice in the header (logo image + adjacent `PACTA — AI` div)? Design intent vs. leftover from a logo swap.
- Was the choice to lead the H1 with pain rather than product name validated against any audience (cold-traffic test, qual interviews), or is it a heuristic call?
- Are there testimonials / sample transcripts / clinician advisors that could go on the page but are intentionally withheld for now (privacy / brand)?
- Was a sticky / repeating mobile CTA considered and rejected, or just not built yet?
